How a bisect runs

You give it a good commit and a bad one. It returns the culprit, the size of the slowdown with an interval, and what the GPU time cost.

  1. Confirm the slowdownMeasure both ends three times. Stop unless the bad end is at least 3% slower with 90% confidence.
  2. Pick the next commitThree agents vote: one halves the range, one reads commit messages, one confirms an edge. A fixed referee decides.
  3. Measure and classifyBenchmark that commit on the A100. A Welch interval labels it fast, slow, or unclear; unclear earns more runs.
  4. Verify and reportRe-measure the culprit against its parent, then write a report anyone can re-render offline.

Decides locally

$0. Bisect driver, statistics, agent orchestration and reports run on your laptop. Every agent answer is schema-checked; a bad or missing answer falls back to a deterministic choice, so runs finish without a key.

Measures on Modal

$2.10 an hour. One warm A100-40GB serves each commit's vLLM build. The GPU is pinned and re-checked on every trial; benchmark runs are the only thing that costs money.

# find the culprit between two commits
perfpilot bisect --good <sha> --bad <sha>
# try serve flags to win speed back
perfpilot tune --commit <sha>
# score the agents on 17 scenarios, no GPU
perfpilot bench --suite all --seeds 20

What happened on real GPUs

Each trial plants a known slowdown (--enforce-eager) at a hidden commit in a frozen 16-commit range. The agents never see where.

Tuning serve flags

Six flag changes on one commit: prefix caching, two batch-token budgets, async scheduling, FP8 KV cache, 256 sequences. None beat the baseline by the required 2%; FP8 can't run on an A100 and was rejected. Baseline kept, answer quality held, $1.60. Open the tuning report.

Bench and agent swarm

perfpilot bench runs the real bisect driver against a simulated A100 with noise, collapsed runs, preempted workers, broken builds and drift. It scores three ways of picking commits across 17 scenarios and 20 seeds, and logs the score for each git commit.

Scores, 20 seeds × 17 scenarios

Score = 100 × correct − 200 × wrong − 2 × measurements, averaged per run. Exact is below 100% only where a range is the honest answer: broken builds next to the culprit, and 5% slowdowns at the run cap.
