# PerfPilot

Agent that keeps a vLLM deployment of a Meta open model fast.
**PerfBisect** finds the first slow commit; **TuneSmith** recovers speed via
serve flags. Every claim is benchmark-verified with intervals — never vibes.

Push the Frontier: an agent that gives vLLM maintainers a new capability —
per-commit regression culprits with statistical proof. One-line usage:
`perfpilot bisect --good G --bad B` → culprit + interval + GPU $;
any report re-renders offline via `perfpilot report runs/<run-id>`.

Indie track, Push the Frontier. Plan and spec: [PLAN.md](PLAN.md), [SPEC.md](SPEC.md).
Interactive diagrams: [docs/](docs/index.html).

## How it works

Two planes. A free local control plane **decides and proves**; a metered Modal
A100 plane **measures**. The Baseten brain (`muse-spark-open`) only advises —
which commit to probe, whether more samples are needed, which flags to try —
and every proposal is schema-validated with a deterministic fallback when no
key is set.

```
bisect --good G --bad B → freeze wheeled range → pick SHA → run_trial (A100)
  → classify (Welch interval) → narrow → verdict: culprit + interval + GPU $
tune --commit C → propose flags → measure → quality gate (50Q bank)
  → best flags + serve_command + fix.patch
```

## Swarm + bench harness ($0 GPU)

`perfpilot bench` scores agent variants on a **simulated A100** (seeded
noise, collapsed-run outliers at the 0.47× factor seen live, metered
setup+run seconds at $2.10/h) across 7 planted scenarios × N seeds, and
appends each run to `bench/scoreboard.jsonl` keyed by git SHA so progress
is tracked per commit.

Variants: `fallback` (deterministic midpoint), `single` (one reasoning
agent), `swarm` — three roles propose the next commit (**bisector** halves,
**code_reader** flags hot-path commit messages, **statistician** probes a
bad hint's parent to pin the edge) and a deterministic **referee** sums
confidence-weighted votes, ties to the most even split. Roles only propose;
bisect still validates every pick, so a bad role costs probes, never a
verdict. `--live-brain` swaps scripted roles for Baseten personas (votes
logged as `swarm_pick` events).

Scripted mode, 20 seeds × **17 scenarios** (7 core + 10 stress:
stacked culprits, broken builds, flaky worker, rig drift, 5% borderline,
transient regression, speedup, 64-commit range, hint spam, edge culprit) —
`perfpilot bench --suite all --seeds 20`:

| Variant | Correct | Exact | Wrong | Probes/run | $/run (sim) | Score |
|---|---|---|---|---|---|---|
| fallback | 100% | 91% | 0 | 8.74 | $1.73 | 82.5 |
| single | 100% | 91% | 0 | 8.79 | $1.74 | 82.4 |
| swarm | 100% | 91% | 0 | 8.61 | $1.71 | 82.8 |

Score = 100·correct − 200·wrong − 2·probes (per-run means). "Exact" < 100%
only where a range is the honest answer (broken builds around the culprit,
5% borderline drops at the 8-run cap).

Failures the harness surfaced, each fixed test-first with replayed evidence:

| Scenario | Before | After | Fix |
|---|---|---|---|
| outlier (collapsed runs) | 17/20 | 20/20 (40/40 seeds) | drift re-measure uses the endpoint spread guard; when both endpoint sets are contaminated, pool them and drop runs >15% from the median (logged) |
| flaky_worker (10% preemptions) | 16/20, 4 aborts, 11 exact | 20/20, 20 exact | `run_bisect` retries `trial error` outcomes (default 2); build skips never retried; live CLI now tags worker errors as transient instead of as build skips |
| hint_spam (every msg says "kernel") | swarm 20.3 probes | 9.1 | code_reader abstains when >25% of the open range matches — a hint must discriminate |
| code_hint | 9.0 probes | **6.0 (swarm)** | code_reader + statistician confirm-parent combo |

Live Baseten model (`--live-brain`, 7 core scenarios × 3 seeds):

| Variant | Correct | Wrong | Probes/run | code_hint | noisy |
|---|---|---|---|---|---|
| single agent | 100% | 0 | 9.19 | 10.0 | 13.3 |
| swarm | 100% | 0 | 9.71 | **6.0** | 19.0 |

The live swarm wins big where a message points at the culprit and loses on
noise, so overall it is roughly even with one agent. The first live run
exposed ungrounded high-confidence votes; confidence is now checked
against the commit message and the statistician is deterministic.

Known limits, stated: a misleading hint costs ~1 probe (never a verdict);
5% regressions under 1.5% noise need ~17 probes; scripted roles are
heuristics — only `--live-brain` scores the real model.

## Tune (GPU, `runs/tune-20261101-150900`, ~$1.60)

Base `e5196e29`, 6 candidates max, live brain proposing, 50Q quality gate:
prefix-caching, batch-tokens 8k/16k, async scheduling, fp8 KV, seqs-256 —
five showed no measurable uplift (interval not fully above +2%), fp8 errored
(A100 lacks Hopper FP8) and was recorded as a rejection while the run
continued. Baseline kept, quality held, `status=done`. An honest negative:
this workload on this commit is already at its flag optimum.

Quality-gate meaning, stated plainly: the bank scores exact-match accuracy
(percent scale) on greedy ≤32-token answers from Llama-3.2-1B, whose
baseline is 2.0% — the gate is a *relative* drop check (≤2pts), not an
absolute bar. "Quality held" means no candidate made answers worse, not
that answers are good.

## Known limitation

A culprit at the very first commit of the range is undetectable by
construction: every commit measures slow, so the range contains no clean
baseline and no transition. The driver honestly reports `no_regression`
instead of fabricating a culprit (locked in by
`test_eval_protocol_first_commit_reports_no_regression`). Only a pre-range
baseline could distinguish this case. The eval protocol therefore plants at
[1, 15] — index 1 is the lowest detectable position.

## Setup

Requires Python 3.12 and [uv](https://docs.astral.sh/uv/).
Key from env or local `.env` (gitignored, never logged); without a key the
drivers run deterministic fallbacks.

```sh
uv sync --group dev
printf 'BASETEN_API_KEY=%s\n' 'your-key' > .env
uv run perfpilot bisect --good <sha> --bad <sha>
uv run perfpilot tune --commit <sha>
uv run perfpilot report runs/<run-id>   # watch: live refresh
uv run perfpilot demo runs/<run-id> --speed 1.5  # replay a run, no GPU/key
uv run perfpilot eval --trials 2        # GPU; needs quota + approval
make test   # pytest
make bench  # $0 swarm/variant scoreboard, 17 scenarios (make bench-record to log)
make lint   # ruff check + format
```

Each run writes `runs/<id>/`: `config.yaml`, `events.jsonl`, `report.html`,
`results/`, `logs/` (+ `fix.patch` for tunes). Any report re-renders offline:
`perfpilot report runs/<id>`.
